# vezilka - датасет на македонски говор

Датасет со парови **(аудио исечок, проверен транскрипт)** на македонски јазик,
изграден од кратки видеа со вградени титли.

Клучна карактеристика: **секој транскрипт е прегледан и потврден од човек**.
Автоматиката дава само прв предлог - конечниот текст го одобрува човек.

---

## Резултат

Датасетот е во **`dataset/`**.

| | |
|---|---|
| **Клипови** | **2024** |
| **Вкупно аудио** | **2 часа и 26 минути** |
| Изворни видеа | 119 |
| **Рачно поправени транскрипти** | **1201 (59%)** - 88.3 мин |
| Прегледани и потврдени како точни | 823 (41%) |
| Означени како дијалект | 305 клипа од 25 видеа (14.7 мин) |
| Стандарден говор | 1719 клипа (121.8 мин) |
| Формат | 16 kHz mono WAV + CSV |
| Просечна должина на клип | 4.0 сек (медијана 3.5s, макс 26.4s) |

---

## Проблемот

Видеата содржат титли „испечени" во самата слика - не се одделна датотека.
Наивниот пристап (извади го текстот со OCR и земи го како транскрипт) даде
податоци што **не се употребливи**:

| Проблем | Пример / мерка |
|---|---|
| OCR на стилизирана кирилица греши | `БЕЗ ИЗГОРЕНИЦИ` → `BE3 ИЗGOREНИЦИ` |
| Титлот не е порамнет со говорот | отстапување до ±1 секунда |
| Фрагментирани сегменти | ~78% од клиповите беа ≤1 секунда |
| Изгубена типографија | ~52% само со ГОЛЕМИ БУКВИ |

Транскрипт полн со грешки и поместен во време е полош од никаков - учи на
погрешен правопис и погрешно порамнување.

## Методологијата

Наместо OCR-от да биде извор на вистината, тој се користи како **втора,
независна проверка**:

```
видео ──► ffmpeg ──► аудио 16 kHz mono
                        │
        ┌───────────────┴───────────────┐
        ▼                               ▼
  faster-whisper (large-v3)       PaddleOCR (кириличен)
  транскрибира аудио,             чита вградени титли
  VAD сегментација                од сликата
        │                               │
        └──────────────┬────────────────┘
                       ▼
        споредба за ист временски прозорец -
        отфрла сегменти каде текстот не се
        совпаѓа со титлот (знак за поместеност
        или за погрешно препознавање)
                       ▼
           👤 РАЧНА ПРОВЕРКА ОД ЧОВЕК
              (слушање + корекција)
                       ▼
                dataset/
```

**Транскриптот доаѓа од Whisper** - со правилни мали/големи букви и интерпункција.
OCR-от служи за да потврди дека зборовите се точни и дека аудиото е порамнето
со нив. Каде двата извора се разидуваат сериозно, сегментот се отфрла.

### Филтрирање на неупотребливо аудио

Четири нивоа, од најрано до најдоцна:

1. **VAD** (детекција на говор) - тишината, музиката и долгите паузи воопшто не
   стануваат сегмент
2. **Должина** - задржани се само сегменти од 1 до 30 секунди
3. **Доверба на моделот** - `no_speech_prob`, `avg_logprob`, `compression_ratio`
   (последниот ги фаќа повторувачките халуцинации врз музика и аплауз)
4. **Смисленост на текстот** - минимум 2 збора, минимум 3 кирилични букви,
   најмногу 50% латиница, филтер за брендови и повторувања

### Споредбата Whisper ↔ OCR

Две метрики, обете мора да поминат:

| Метрика | Што фаќа |
|---|---|
| `token_sort_ratio ≥ 58` | општа сличност на двата текста, редоследот не е важен |
| `word_recall ≥ 0.55` | колкав дел од изговорените зборови (≥3 букви) навистина се на екранот |

Само првата се лаже кога OCR-прозорецот фатил вишок текст (лого, следен титл) -
неколку заеднички зборови ја надуваат оцената. Втората бара **мнозинството
изговорени зборови навистина да се видливи**. Заедно се сигурни.

### Рачната проверка - суштината на проектот

Автоматиката завршува со предлог. Потоа **човек го слуша секој клип** и го
поправа текстот каде што моделот погрешил. Тоа е забележано во податоците:

| Колона | Улога |
|---|---|
| `whisper_text` | оригиналниот автоматски транскрипт |
| `corrected_text` | текстот по рачна проверка - **ова е вистинскиот label** |
| `was_edited` | `yes` ако човек го менувал, `no` ако автоматскиот бил точен |

Влијанието на рачната работа е **мерливо, не само тврдено**: 1201 од 2024 клипа
(59%) се фактички поправени.

Пример:
> `whisper_text`: „детето се здобило со повеќе каснување и повреди, **мегу** кои и во пределот на лицето, **угото**"
> `corrected_text`: „детето се здобило со повеќе каснување и повреди, **меѓу** кои и во пределот на лицето, **увото**"

### Означување на дијалект

Секое видео е дополнително класифицирано како дијалектно или стандардно.
Автоматски предлог врз основа на зборови-маркери (`шо`, `абе`, `кере`, `арно`…),
потоа **рачна проверка на сите 119 видеа**. Резултат: 25 дијалектни видеа
(305 клипа, 14.7 мин).

Тоа овозможува податоците да се користат или оценуваат одделно по регистар.

## Структура на датасетот

```
dataset/
├── clips/*.wav        2024 клипа, 16 kHz mono PCM
└── metadata.csv
```

| Колона | Значење |
|---|---|
| `file_name` | патека до аудио клипот |
| `video` | од кое изворно видео потекнува |
| `start`, `end`, `duration` | позиција во оригиналното видео (секунди) |
| `whisper_text` | автоматски транскрипт |
| `corrected_text` | **проверен текст - ова се користи како label** |
| `was_edited` | дали човек го менувал (`yes`/`no`) |
| `dialect` | дијалект (`yes`) или стандарден говор (`no`) |

Нема колона за поделба train/test - таа се пресметува при употреба, **по видео**
(детерминистички хеш), за да не завршат клипови од истиот говорник во двата дела.

### Употреба за тренирање

Целта на проектот е **самиот датасет**, не трениран модел. Форматот е стандарден
и директно употреблив за дообучување на Whisper или друг STT модел - паровите
`clips/*.wav` + `corrected_text` се токму она што таквите библиотеки го очекуваат:

```python
from datasets import load_dataset
ds = load_dataset("csv", data_files="dataset/metadata.csv")
# аудиото се вчитува од колоната file_name, label-от е corrected_text
```

Колоните `was_edited` и `dialect` овозможуваат филтрирање - на пример, тренирање
само на рачно поправените примери, или одделна евалуација на дијалектниот говор.

## Работен тек

### 1. Собирање видеа
```bash
.venv/bin/python download_videos.py links.txt
.venv/bin/python download_videos.py "https://www.tiktok.com/@profil" --max 200
```
Веќе симнатите се прескокнуваат автоматски.

### 2. Обработка на видеата
```bash
.venv/bin/python build_dataset.py                  # целосно
NUM_WORKERS=3 .venv/bin/python build_dataset.py    # паралелно
WHISPER_MODEL=small MAX_VIDEOS=2 .venv/bin/python build_dataset.py   # брз тест
```
Кешира по видео во `_cache/`, па повторните прогони обработуваат само нови
видеа. Менување само на праговите трае секунди, не часови.

**За `NUM_WORKERS`:** RAM е ограничувачки фактор, не CPU. Три работника ≈ 10-12 GB
само за модели.

### 3. Рачна проверка
Метаподатоците се отвораат во Excel, се поправа текстот каде треба, се зачувува
како `metadata_popravka.csv`.

Алтернатива во терминал:
```bash
.venv/bin/python review_dataset.py         # слуша клип по клип, прашува за корекција
```

### 4. Спојување во финален датасет

Актуелниот `dataset/` е составен од повеќе сесии на обработка и рачна проверка,
спојувани со еднократни скрипти. Тие се веќе искористени и отстранети - историјата
е зачувана во git ако процесот треба да се повтори или прегледа:

```bash
git log --oneline -- merge_v2.py merge_exports.py
git show <commit>:merge_v2.py
```

Логиката беше: аудио клиповите и временските податоци се земаат од сировиот излез
(`metadata_full.csv`), поправениот текст од рачно уредената верзија
(`metadata_popravka.csv`), а видеата каде ниеден ред не е поправен се прескокнуваат
како непрегледани.

### 5. Означување дијалект
```bash
.venv/bin/python label_dialect.py make  --dataset dataset
# рачна проверка на dialect_videos.xlsx / .csv
.venv/bin/python label_dialect.py apply --dataset dataset
```
`make` создава листа со автоматски предлог по видео. По рачната проверка,
`apply` ја запишува `dialect` колоната во метаподатоците.

### 6. Проверка на датасетот
```bash
.venv/bin/python inspect_dataset.py              # збирна статистика
.venv/bin/python inspect_dataset.py --play 8     # слушни 8 клипа
.venv/bin/python inspect_dataset.py --grep индукц
.venv/bin/python tests/test_pipeline.py          # 16 unit-тестови
```

## Опис на датотеките

| Датотека | Улога |
|---|---|
| `build_dataset.py` | pipeline-от: видео → аудио → Whisper + OCR → клипови и метаподатоци |

## Параметри на pipeline-от

На врвот на `build_dataset.py`:

| Константа | Значење | Вредност |
|---|---|---|
| `WHISPER_MODEL` | големина на моделот | `large-v3` |
| `AGREEMENT_THRESHOLD` | праг за совпаѓање Whisper↔OCR | 58 |
| `WORD_RECALL_MIN` | дел од изговорените зборови што мора да се на екранот | 0.55 |
| `OCR_TIME_MARGIN` | толеранција при спарување OCR со сегмент | 1.0s |
| `MIN/MAX_SEGMENT_SECONDS` | граници за должина на клип | 1-30s |
| `OCR_FPS` | фрејмови во секунда испратени на OCR | 1.0 |
| `NUM_WORKERS` | паралелна обработка | 1 |
